# [섹션 분리 — 계층 구조]
- 논리적으로 같은 주제 → 하나의 카드(se-div) 안에 묶기.
- 다른 성격(기간 vs 참여방법 vs 보상목록)일 때만 별도 카드로 분리.
- 소제목(■·▶·번호)이 하나의 주제 아래 있으면 카드 안에서 소제목으로 처리. 별도 카드 금지.
- 계층: se-contents > 대카드(se-div) > 소섹션(내부 se-div) — 과도한 분리 FAIL.

## ⚠️ 섹션 카드 내부 "카드 안 카드" 절대 금지 (위반 시 즉시 FAIL)
섹션 카드(${surfaceColor} bg 가진 se-div) **안에서** 또 다른 `background-color` / `border:1px solid` / `border-radius` 가진 se-div 로 콘텐츠를 감싸는 행위 금지. 카드 안에 또 카드 들어가면 시각 위계 무너지고 섹션마다 일관성 깨짐.

**룰:** 섹션 카드 안의 내부 se-div 는 **레이아웃 그루핑 전용** (margin, padding, border-top 만 허용). `background-color` / `border:1px solid` / `border-radius` 가진 내부 se-div 는 새 카드로 인식되어 FAIL.
- 모든 섹션은 반드시 형제(Sibling)로 수직 적층. 중첩(Nesting) 금지.
- **절대 규칙: 하나의 콘텐츠 내 모든 섹션은 동일한 디자인 패턴 사용. 섹션마다 다른 스타일(카드형/border-left형/풀폭형) 혼합 금지 → 즉시 FAIL.**

## 카드 묶음 규칙 (Cards Grouping)

### (A) 같은 레벨 형제 섹션이 여러 개일 때 — **각자 독립 카드**
- 이벤트 1~N 처럼 **반복되는 형제 섹션**은 각각이 자기 배경·radius·padding 을 갖는 **독립 카드**로 구성.
- ❌ 금지 패턴: "외곽 래퍼 카드 1개 + 내부 divider(border-top) 로 N개 구분" — 시각적 묶음은 가능하지만 각 섹션의 독립성을 해치고, 카드 내부에 카드가 중첩되는 것처럼 보임.
- ✅ 권장 패턴: 각 섹션이 `se-div` 카드 + 섹션 사이 `<p style="height:24px;margin:0;"></p>` 간격.

### (B) 중첩 카드 — **조건부 허용**
- 기본 원칙: 외곽 카드 안에 또 다른 배경 카드 **불필요**.
- **예외(허용)**: 섹션 내부에 시각적으로 **별개 단위로 인지되어야 할 서브 블록**이 있을 때만 중첩 카드 사용.
  - 예: 강조 박스 (경고/주의/요약), 다른 성격의 소단원(이벤트 안의 "추가 보상 안내"), 인용 박스
  - 판단 기준: "읽는 사람이 이 부분을 본문과 **다른 덩어리**로 인지해야 하는가?" — 그렇다 → 중첩 카드 OK
- 중첩 카드 스타일은 외곽 카드와 톤 차이가 나도록 배경 명도를 조절 (surface 톤 tint). 외곽과 동일 배경이면 중첩 의미 없음 → FAIL.

### (E) 섹션 depth 판정 (형제 vs 자식)
- 같은 depth 의 형제 섹션(예: "이벤트 기간", "이벤트 내용")은 반드시 **같은 레벨**에 배치. 기간만 카드 안, 내용만 카드 밖 같은 비대칭 금지.
- 탭 바가 특정 섹션("이벤트 내용")의 **자식**이면, 탭 바와 탭 콘텐츠는 그 섹션의 카드 **밖**에 나와야 함(상위 카드 내부가 아닌 형제로).
  - 예: `[이벤트 내용 평문]` → `[탭 바]` → `[이벤트 1 카드]` → `[이벤트 2 카드]` ... 는 모두 평문-형제 구조.

### (F) 외곽 래퍼 max-width
- HERO + 컨텐츠 전체를 감싸는 **최외곽 래퍼**의 `max-width` 는 `basicInfo.컨텐츠 영역 너비` 값 사용 (예: `876px`). 하드코딩 금지.
- 외곽 래퍼가 `max-width` 를 책임지면 **내부 블록에서는 max-width 제거** (팝업 딤 오버레이가 `closest('div[style*=max-width]')` 로 최외곽을 찾아야 HERO 까지 딤 커버).
- 외곽 래퍼 필수 스타일: `position:relative;width:100%;max-width:{basicInfo.컨텐츠 영역 너비};margin:0 auto;box-sizing:border-box;display:block;`
- ⚠️ 이는 **디자인 관점 레이아웃 규칙**. 팝업 딤 동작 로직 자체(`closest`, createElement) 는 절대 건드리지 말 것.

## 헤딩 유형별 처리 규칙 (⚠️ 위반 시 FAIL)

| 원고 패턴 | 처리 방식 |
|----------|----------|
| `■ 제목` / `▶ 제목` | 번호 배지 없이 소제목으로 처리. `<p style="font-weight:900;color:${accentColor};...">■ 제목</p>` — 배지(원형) 생성 금지 |
| `N. 제목` (숫자+점) | 번호 배지(원형) + 제목 텍스트. **제목에서 `N.` 앞 번호 반드시 제거.** 배지에만 번호 표시 |
| `- 내용` / `• 내용` | 불릿 리스트. `<p style="...">` 로 렌더링, 앞에 `•` 또는 `–` 인디케이터 유지. `ul/li` 금지 |
| `(수정)` `(추가)` 등 태그 | 원고 텍스트 그대로 출력. 임의 스타일링 금지 |
