# 이미지 파이프라인 계약 (Image Pipeline Contract)

**적용 범위**: HTML 결과물을 생성하는 **모든 주체 · 모든 Route** 에 무조건 적용.
- **Route 1**: promo-editor UI (app.js → Gemini)
- **Route 2**: Claude Code 단독 (Claude 가 직접 HTML 작성)

두 Route 모두 본 계약의 **3단계 파이프라인을 동일한 순서로 수행**해야 하며, 결과물의 포맷·검증 기준은 **100% 동일**해야 한다. 어느 한 단계라도 FAIL 시 다음 단계 진입 금지, 결과물 배포 금지.

**상위 계약**: `orchestration_contract.md` — 본 계약은 그 1·3단계의 서브계약.

**기존 수동 플로우 보호**: 본 계약은 자동화 경로에 적용된다. 유저가 수동으로 에셋을 업로드하고 작업하는 기존 플로우는 본 계약의 강제 조건 밖이며, **자동화 코드가 수동 플로우를 훼손해서는 안 된다** (orchestration_contract §회귀 방지 참조).

---

## 🚨 최상위 원칙 (한 줄 요약)

> **이미지 수집이 끝나기 전에는 HTML 한 줄도 쓰지 않는다.**
> **노션에 존재하는 이미지는 소스 불문(S3든 로컬 컨텐츠 폴더든) 전부 "컨텐츠_에셋" 폴더에 실물로 존재해야 한다.**
> **수집 완료 검증 실패 시 즉시 중단, HTML 작업 진입 금지.**

---

## 폴더 모델 (2-Folder Paradigm)

본 계약은 **2개의 폴더**를 사용한다. 혼동 금지.

| 폴더 | 용도 | 위치 | 파일명 규칙 | 영속성 |
|---|---|---|---|---|
| **① 컨텐츠_에셋 폴더** | 이미지 **마스터 라이브러리**. 노션에 등장하는 모든 이미지 원본을 보관. HTML 생성 시 참조 소스. | 노션 `기본정보.컨텐츠 에셋 경로` **또는** `기본정보.로컬 저장 경로/컨텐츠_에셋/` | **원본 파일명 유지 · 해시 없음** | **영구** (재파싱 시 동일 파일명 덮어쓰기) |
| **② PROMO_xxx 최종 산출물 폴더 + ZIP** | 배포 가능한 결과물. HTML + 해시 이미지 폴더가 포함된 self-contained 패키지. | 노션 `기본정보.로컬 저장 경로` | 폴더 16자 해시, 파일 8자 해시 | 매 빌드마다 재생성 |

> **③ 임시 폴더는 더 이상 사용하지 않는다.** 이전 판본의 `_staging_<timestamp>/` 모델은 폐기.

## 파이프라인 개요

```
[1. INGESTION — 컨텐츠_에셋 폴더에 마스터 라이브러리 구축]
   ├─ 노션 기본정보에서 "컨텐츠 에셋 경로" 확인
   │    ├─ 있음 → 그 경로를 마스터 폴더로 사용
   │    └─ 없음 → "로컬 저장 경로/컨텐츠_에셋/" 생성
   ├─ 노션 ![](S3 URL) → 다운로드 → 컨텐츠_에셋 폴더 (원본 파일명 · 동명 덮어쓰기)
   └─ (마커) / [마커] → 노션 내 이미지 또는 기존 폴더 파일과 매칭 → 필요 시 복사
          ↓
   ✅ 수집 완료 검증 (마커 수 == 컨텐츠_에셋 폴더 실물 파일 수)
          ↓ (FAIL 시 중단)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[2. GENERATION — HTML 생성]
   └─ 컨텐츠_에셋 폴더 파일만 참조. 없는 파일 img 태그화 금지
   └─ src 는 placeholder (`__ASSET__<원본파일명>`) 또는 컨텐츠_에셋 상대 경로
          ↓
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[3. FINALIZE — 최종 산출물 생성 (로컬 저장 경로)]
   ├─ PROMO_<timestamp>/ 생성 (로컬 저장 경로 하위)
   ├─ 16자리 해시 서브폴더 생성 (generateHashString(16))
   ├─ 컨텐츠_에셋에서 사용된 이미지만 해시 폴더로 복사
   ├─ 각 파일명 8자리 해시 rename (generateHashString(8))
   ├─ HTML 내 placeholder → `./<16자리해시>/<8자리해시>.ext` 치환
   └─ ZIP export (PROMO_SLICED / PROMO_html 구조)
          ↓
   ✅ 최종 검증 리포트 출력 (무조건)

   ⚠️ 컨텐츠_에셋 폴더는 건드리지 않는다 (영구 보존).
```

## 1단계 — INGESTION (컨텐츠_에셋 폴더 구축)

### 1.1 컨텐츠_에셋 폴더 결정

노션 `기본정보` 테이블 파싱 후:

```
if (노션.기본정보["컨텐츠 에셋 경로"] 값 존재):
    ASSET_DIR = 그 경로 (OS 별 정규화)
else:
    ASSET_DIR = <노션.기본정보["로컬 저장 경로"]>/컨텐츠_에셋/
    if not exists(ASSET_DIR):
        mkdir(ASSET_DIR)
```

- **OS별 경로 치환은 자동** (host/share 는 노션 경로에서 추출, 아래는 형식 예시)
  - `smb://<HOST>/<SHARE>/...` →
    - macOS: `/Volumes/<SHARE>/...`
    - Windows: `\\<HOST>\<SHARE>\...`
    - Linux: `/mnt/<share-lowercase>/...`
  - OS 감지 후 정규화 함수로 처리 (`navigator.platform` / `os.platform()` / `platform.system()`)
- **폴더명 고정**: 자동 생성되는 경우 반드시 `컨텐츠_에셋` (한글, 언더스코어). 타 이름 금지.
- **해시 금지**: 컨텐츠_에셋 폴더명에도, 그 하위 파일명에도 해시 적용 금지.

### 1.2 수집 대상 — 노션에서 이미지 전수 스캔

노션 원고 본문 전체 재귀 스캔 (테이블 셀 / callout / 툴팁·팝업 내부 포함):

| 소스 | 패턴 | 해결 방식 |
|---|---|---|
| S3 삽입 이미지 | `![](https://prod-files-secure.s3...)` | HTTP GET 다운로드 → 컨텐츠_에셋 폴더 저장. **기존 동명 파일과 충돌 시 block id 기반 suffix 부착 (§1.3.B)** |
| 괄호 마커 | `(filename.ext)` / `(shortname)` | 컨텐츠_에셋 폴더 내 파일명 매칭. 미존재 시 노션 본문 내 동일 이름 이미지 / 기존 에셋 경로에서 복사 |
| 대괄호 마커 | `[filename.ext]` | 동일 |
| 확장자 없는 shortname | `(Item1)`, `(char47)` 등 | 컨텐츠_에셋 폴더에서 `{name}.(png\|jpg\|jpeg\|webp\|svg)` 순서로 탐색 |

### 1.3 파일명 규칙

- **원본 파일명 유지** — 해시 처리는 3단계에서만
- 대소문자 구분 없이 매칭하되 저장 시 실제 파일명 유지.

수집 소스별 덮어쓰기 정책이 **다르다**. 혼동 금지:

#### 1.3.A 마커 소스 — `(filename.ext)` / `[filename.ext]`
- 마커는 기존 컨텐츠_에셋 폴더 파일을 **참조**하는 것이 목적. 동일 파일명이면 동일 에셋으로 간주.
- 로컬 기존 컨텐츠 폴더에서 복사해 올 때 같은 이름이 이미 있으면 **덮어쓰기 허용** (재파싱 반영).

#### 1.3.B S3 페이지 삽입 이미지 — `![](https://prod-files-secure.s3...)`
- 노션 본문 블록에 삽입된 이미지. **컨텐츠_에셋의 기존 파일과 우연히 이름이 같아도 서로 다른 이미지일 수 있다.**
- **원칙: 덮어쓰기 금지.** 컨텐츠_에셋에 **이미 동일 파일명이 존재하면 suffix 를 붙여 구분해 저장**한다.
  - suffix 규칙: `<base>__n<8자해시>.<ext>` (예: `item.png` → `item__nA1b2C3d4.png`)
  - 해시는 노션 block id 기반 (동일 블록의 재다운로드는 같은 해시 → 이 경우는 덮어쓰기 OK)
- 동일 노션 block 의 재파싱(내용 갱신) 시: 같은 suffix 가 재생성되므로 자연스럽게 덮어쓰기 → 항상 최신 유지.
- HTML 생성 단계에서 해당 블록의 이미지 src 는 suffix 붙은 실제 저장 파일명을 사용.

### 1.4 재파싱 (노션 이미지 변경 반영)

- **마커 파일 (1.3.A)**: 동일 파일명 → 덮어쓰기
- **S3 페이지 삽입 이미지 (1.3.B)**: block id 기반 suffix 로 저장되므로 같은 블록의 재파싱은 자동 덮어쓰기, 다른 블록이 동일 원본 파일명을 써도 서로 다른 suffix → 공존
- 노션에서 이미지를 삭제한 경우 → 컨텐츠_에셋 폴더 파일은 **보존** (다른 프로모에서 재사용 가능)
- 노션에서 신규 이미지 추가 → **추가 다운로드**
- 규칙: **컨텐츠_에셋 폴더는 append-only 기본 · 허용된 경우에만 overwrite (1.3.A 마커 동명, 1.3.B 동일 block id)**

### 1.5 수집 완료 검증 (FAIL 게이트)

1단계 종료 전 아래 조건 모두 만족해야 함. 하나라도 실패 시 **즉시 중단**:

```
✅ 노션 원고에서 발견된 이미지 마커 + S3 URL 수 = N (unique)
✅ 컨텐츠_에셋 폴더 내 해당 파일 전부 존재: N개 매칭 ✅
✅ 미확보 마커 리스트 = [] (빈 배열)
```

미확보가 있으면:
- 사용자에게 누락 리스트 출력 (마커명 + 예상 소스 경로)
- 수동 보강 후 재실행 유도
- **2단계 진입 불가**

## 2단계 — GENERATION (HTML 생성)

### 2.1 생성 주체 책임

- Claude / Gemini 모두 **오직 컨텐츠_에셋 폴더에 있는 파일만 참조**해서 HTML 작성
- 컨텐츠_에셋에 없는 파일을 `<img>` 태그로 쓰면 FAIL
- 마커 형태 처리:
  - TD 내부 마커 + 텍스트 → `<img>` 인라인 + 텍스트 유지 (축약 금지)
  - 단독 문단 `<p>(filename)</p>` → 블록 `<img>` 로 대체

### 2.2 생성 시 src 표기 (택 1)

- **권장: placeholder** — `src="__ASSET__<원본파일명.ext>"` (3단계에서 일괄 치환)
- 또는 컨텐츠_에셋 상대 경로 — 단 3단계에서 반드시 해시 경로로 최종 치환되어야 함

### 2.3 GENERATION 금지 사항

- 컨텐츠_에셋 폴더 밖 이미지 참조 금지 (외부 URL 포함)
- 노션에 없는 임의 이미지 플레이스홀더 생성 금지
- 마커 텍스트 그대로 HTML에 남기기 금지 (`<td>(item1) ...</td>` 상태로 종료 시 FAIL)

## 3단계 — FINALIZE (최종 산출물 생성)

> ⚠️ 본 단계는 **컨텐츠_에셋 폴더를 수정하지 않는다.** 사용된 이미지를 **복사**하여 별도 산출물 폴더를 만든다.

### 3.1 최종 산출물 폴더 결정

- 위치: 노션 `기본정보.로컬 저장 경로` 하위
- 이름: `PROMO_<timestamp>/` (신규 작업) 또는 기존 폴더 재사용(수정 작업)
- 수정 작업 판별: `detectExistingHash()` 로 기존 해시 폴더 발견 시 → 기존 해시 재사용 or 교체

### 3.2 해시 생성

- **서브폴더 해시**: `generateHashString(16)` — 예: `tyr3cauqhwj6rdyh`
- **파일명 해시**: `generateHashString(8)` — 예: `gm4ibe32` (확장자 유지)

### 3.3 파일 복사 + HTML 치환

1. `PROMO_<timestamp>/<16자리해시>/` 생성
2. 컨텐츠_에셋 폴더 → 해시 폴더로 **복사** (원본 삭제 금지)
   - HTML에 실제 사용된 이미지만 복사 (unused 이미지 복사 금지)
3. 각 파일 rename: `Item1.png` → `gm4ibe32.png`
4. **매핑 테이블** 유지:
   ```json
   {
     "Item1.png":    "gm4ibe32.png",
     "char47.jpg":   "k3fx82mn.jpg",
     "img.png":      "a1b2c3d4.png"
   }
   ```
5. HTML 내 모든 img src placeholder / 컨텐츠_에셋 경로 → `./<16자리해시>/<해시파일명>` 로 치환

### 3.4 ZIP Export

- PROMO_SLICED / PROMO_html 구조 유지 (app.js 기존 규칙)
- ZIP 파일은 `로컬 저장 경로` 에 저장
- PROMO_<timestamp>/ 폴더와 ZIP 은 **공존** (ZIP 은 배포용 사본)

### 3.5 컨텐츠_에셋 폴더 정책

- **절대 삭제/이동/rename 금지.** 영구 마스터 라이브러리.
- 복사만 허용.

### 3.6 최종 검증 리포트 (무조건 출력)

작업 완료 선언 **전**에 아래 리포트를 사용자에게 출력. 한 항목이라도 ✗면 "완료" 선언 금지.

```
📸 이미지 파이프라인 최종 검증

[1단계 INGESTION — 컨텐츠_에셋]
- 컨텐츠_에셋 폴더 경로: <ASSET_DIR>
- 노션 이미지 마커 + S3 URL 총 개수: N (unique)
- 컨텐츠_에셋 폴더 실물 매칭 파일 수: N ✅
- 미확보: 0건 ✅

[2단계 GENERATION]
- HTML <img> 태그 수: N (본문) + M (숨김 팝업 블록, 있는 경우)
- 컨텐츠_에셋 밖 이미지 참조: 0건 ✅
- 잔존 텍스트 마커 (filename.ext) / [filename.ext]: 0건 ✅

[3단계 FINALIZE]
- 최종 산출물 폴더: <로컬 저장 경로>/PROMO_<timestamp>/
- 해시 서브폴더: <16자해시>/
- 해시 폴더 실물 파일 수: N (unique, 실사용 이미지만)
- 파일명 매핑 테이블: (전부 나열)
   ✅ Item1.png    → ./<hash>/gm4ibe32.png
   ✅ item2.png    → ./<hash>/k7x9m2qp.png
   ✅ char47.jpg   → ./<hash>/f4h8j2mx.jpg
   ... (전부)
- HTML 내 <img src> 전부 ./<hash>/ 로 시작: ✅
- 잔존 placeholder (__ASSET__) / 컨텐츠_에셋 경로: 0건 ✅
- 컨텐츠_에셋 폴더 무변경 (복사만): ✅
- ZIP export: 완료 ✅

총괄: PASS / FAIL
```

**리포트 미출력 = 작업 미완료.** 사용자에게 "완료"라고 보고하는 순간 FAIL.

## 워크플로별 강제 방식

### A. promo-editor (app.js)

- **1단계**: `ingestNotionAssets(notionPageId)` 함수 추가
  - 노션 파싱 직후 자동 호출
  - OS 감지 → 컨텐츠_에셋 폴더 결정 (존재 확인 / 필요 시 생성)
  - S3 URL 다운로드 + 로컬 에셋 매칭
  - 동일 파일명 덮어쓰기
  - 파일들을 `contentAssetLibrary` (filename → dataURL) 에 주입 → 좌측 하단 컨텐츠 에셋 업로드 영역에 자동 반영

- **2단계**: 기존 `runImageMatching` 이 자동 처리 (마커 → `<img>` 치환)
- **3단계**: `finalizeExport()` — 로컬 저장 경로에 PROMO_xxx/ 생성 + 해시 처리 + ZIP + 검증 리포트
- **검증 실패 시**: UI 팝업 + 누락 리스트 출력, ZIP export 버튼 비활성화
- **회귀 방지**: 유저가 수동으로 컨텐츠 에셋 업로드 영역에 파일을 드롭하는 기존 동작은 그대로 유지. 자동 ingestion 은 **추가 주입**만 수행.

## FAIL 조건 총정리

아래 중 하나라도 발견되면 즉시 FAIL, 작업 종료 불가:

- ❌ 1단계 수집 완료 전 HTML 생성 시작
- ❌ 1.5 검증 미수행 / 실패한 채로 2단계 진입
- ❌ 노션의 S3 이미지가 컨텐츠_에셋 폴더에 없음
- ❌ 노션 마커에 해당하는 파일이 컨텐츠_에셋 폴더에 없음
- ❌ HTML `<img src>` 가 컨텐츠_에셋 폴더 밖 (또는 3단계 후 해시 폴더 밖) 을 가리킴
- ❌ HTML에 텍스트 마커 `(filename.ext)` / `[filename.ext]` 잔존
- ❌ 3단계 후 HTML src에 `__ASSET__` / `컨텐츠_에셋/` 잔존
- ❌ 컨텐츠_에셋 폴더 자체에 해시 적용
- ❌ 컨텐츠_에셋 폴더 삭제 / rename / 이동
- ❌ S3 페이지 삽입 이미지가 기존 컨텐츠_에셋 동명 파일을 **덮어써서** 마커 매칭용 원본을 훼손 (§1.3.B 위반)
- ❌ 3.6 검증 리포트 미출력
- ❌ 검증 리포트 없이 사용자에게 "완료" 선언
